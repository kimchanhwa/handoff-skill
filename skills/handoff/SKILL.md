현재 세션의 작업 상태를 인수인계 파일로 남기거나, 남긴 파일을 읽어 작업을 이어받는다.

## 입력 처리

입력: $ARGUMENTS

- 비어 있으면 **저장 모드**로 진행한다.
- `resume`이면 **재개 모드**로 진행한다.
- 그 밖의 값이면 사용법(`/handoff`, `/handoff resume`)을 알려 주고 멈춘다.

## 저장 모드

1. 현재 시각을 셸로 확인한다. (PowerShell: `Get-Date -Format yyyy-MM-dd_HHmm`, Bash: `date +%Y-%m-%d_%H%M`)
2. 저장 경로는 `<현재 작업 디렉터리>/output/handoff/<시각>.md`다. 같은 이름의 파일이 이미 있으면 덮어쓰지 않고 `_2`, `_3`을 붙인다.
3. git 저장소인지 확인한다(`git rev-parse --is-inside-work-tree`).
   - git 저장소면 `git status --short`와 `git log --oneline -5`를 확인해 기록에 반영한다. `.gitignore`에 `output/`이 없으면 추가한다.
   - git 저장소가 아니면 이 단계를 건너뛴다.
4. 아래 **기록 항목**에 맞춰 파일을 작성한다.
5. 저장한 파일의 전체 경로와 2~3줄 요약을 출력한다.

## 기록 항목

아래 템플릿을 따른다. **목표·현재 상태·다음 할 일**은 필수이고, 나머지 섹션은 쓸 내용이 있을 때만 넣는다.

```
# Handoff: (작업 한 줄 제목)
기록: YYYY-MM-DD HH:mm

## 목표
(이 작업으로 이루려던 것 1~2줄)

## 현재 상태
- 완료: ...
- 진행 중: ... (어디서 멈췄는지)

## 다음 할 일
1. (바로 실행할 수 있는 첫 단계)
2. ...

## 주의할 점
- 결정: ... (이유)
- 실패한 시도: ... (왜 안 됐는지)
- 미해결: ... (사용자 확인이 필요한 것)

## 관련 파일·명령
- `경로` — 역할
- `명령` — 언제 쓰는지

## git 상태
- 브랜치 / 변경 파일 / 최근 커밋
```

- **분량**: 파일 전체 40줄 이내, 섹션마다 항목 5개 이내로 쓴다. 재개할 때 이 파일이 통째로 컨텍스트에 들어가므로 짧게 유지한다.
- **다음 할 일**: 1번은 다른 맥락 없이 바로 실행할 수 있게 쓴다. "테스트 고치기"가 아니라 "`tests/test_parser.py`의 빈 입력 케이스 통과시키기"처럼 쓴다.
- **주의할 점**: 다음 세션이 같은 실수를 반복하거나 이미 내린 결정을 다시 고민하지 않게 하는 내용만 쓴다.
- **관련 파일·명령**: 코드는 붙여넣지 않고 경로로 대신한다.
- **git 상태**: git 저장소일 때만 넣는다. 변경 파일이 많으면 개수와 주요 파일만 쓴다.

## 재개 모드

1. `<현재 작업 디렉터리>/output/handoff/`에서 파일명 기준으로 가장 최신 파일을 읽는다. 폴더나 파일이 없으면 "남긴 기록이 없어요."라고 알리고 멈춘다.
2. 기록 이후 달라진 점을 확인한다.
   - 기록에 나온 파일이 지금도 있는지 확인한다.
   - 기록에 git 상태가 있으면 지금의 `git status --short`, 최근 커밋과 비교한다.
3. 아래 형식으로 출력하고 사용자 지시를 기다린다. 기록이 오래됐을 수 있으므로 바로 작업을 시작하지 않는다.

```
## 이어받은 기록
(파일 경로, 기록 시각)

## 요약
(3줄 이내)

## 기록 이후 달라진 점
(없으면 "달라진 점 없음")

## 다음 첫 단계 제안
(기록에 남은 할 일 중 가장 먼저 할 것 하나)
```

## 작성 규칙

- 대화와 도구 결과로 확인된 사실만 쓴다. 추측은 쓰지 않고, 확실하지 않으면 "확인 필요"로 표시한다.
- 파일 경로는 정확히 쓴다. 프로젝트 안 파일은 프로젝트 기준 상대 경로로 쓰고, 프로젝트 밖 파일은 `~`로 시작하는 경로로 쓴다. 홈 폴더 밖이면 절대 경로로 쓴다.
- 다음 세션은 이 대화를 볼 수 없다. 이 파일만 읽고 바로 시작할 수 있게 쓴다.
- 기존 handoff 파일은 수정하거나 삭제하지 않는다.
